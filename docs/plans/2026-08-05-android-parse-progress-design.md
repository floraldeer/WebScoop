# Android 解析进度反馈设计

## 目标

在 Android 媒体解析期间提供真实、稳定的时间反馈，并保证“取消解析”文字始终按按钮整体宽度居中。

## 设计原则

1. 不展示无法从 yt-dlp 获取的虚假百分比。
2. 使用 Compose 生命周期管理计时，不创建全局计时器或后台服务。
3. 计时、取消、超时和解析结果必须共享同一解析生命周期。
4. 加载图标不得影响按钮主文案的视觉中心。
5. 保持 macOS 基准配色和现有 Material 3 主题不变。

## 交互设计

点击“解析媒体”后：

- 主按钮切换为可点击的取消状态。
- 按钮内加载图标固定在内容区域左侧。
- “取消解析”按整个按钮内容区域绝对居中。
- 按钮下方显示解析阶段和已用时间。

阶段文案：

- 0–29 秒：`正在解析媒体 · N秒`
- 30 秒及以上：`网络响应较慢 · N秒`
- 45 秒：解析层自动超时并显示现有超时错误。

解析成功、失败、取消或超时后，计时协程自动结束，秒数归零，按钮恢复为“解析媒体”。

## 技术设计

- `LaunchedEffect(isParsing)` 驱动每秒计时。
- `parseElapsedSeconds` 保存当前解析秒数。
- `parseProgressText(seconds)` 生成可单元测试的阶段文案。
- `Box(fillMaxWidth())` 作为按钮内部布局。
- `CircularProgressIndicator` 使用 `Alignment.CenterStart`。
- `Text("取消解析")` 使用 `Alignment.Center`。

## 验收标准

- 开始解析后立即显示 `正在解析媒体 · 0秒`。
- 计时每秒递增，30 秒时切换慢响应文案。
- 点击取消后按钮和计时反馈停止。
- “取消解析”不因加载图标而偏移。
- 原抖音解析、45 秒超时和底层进程取消能力保持有效。
- Android 单测、Lint 和 Debug 构建通过。
